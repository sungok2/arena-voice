## 2. 문항은행 개선 — 구조적 복수정답 위험 제거
- **v2.3.1~2.3.2 결함:** 다른 모듈에서 정답으로 사용한 '참인 문장'을 480개 문항의 오답으로 가져옴. 문항의 단일 최적답 보장 불가.
- **v2.3.3 조치:** 이 480개 문항의 원래 작성된 선택지·정답·해설을 복원함. 이 중 24개는 신규 상황판단형 문항으로 대체하고, 따라서 최종 분포는 **기초형 456개 + 적용형 48개(기존 24개 + 추가 24개)**임.
- **진단 30개:** 같은 문제가 있었던 자동 오답 재활용을 중단하고 작성 당시 문항과 정답을 복원함. 진단 점수에 근거한 임의 '심화 진입' 등 수준 판정을 화면에서 제거함.
- **난이도 한계:** 복원된 456개 기초문항은 지나치게 쉬운 선택지가 많음. 단일 정답에 관한 구조적 문제를 줄였지만 난이도·변별도·정확성을 검증한 것은 아님. 고난도 평가 대신 기초적 자기확인에만 사용함.
- **24개 신규 상황형 원고:** LLM 사실성, MLOps 드리프트, 통계검증, AI API 권한, 데이터 역할/보안, 그룹 누출, 분산 데이터 아키텍처, 정책 충돌, 사업 선정, 데이터 적합성, 라이선스 계약을 다루는 합성 사례 초안. 독립 전문가 검수 없음.
- **자동 역추적 테스트:** `qa/question_integrity_test.js`가 기초형 456개 및 진단 30개에 대해 원래 문제·정답 텍스트·해설·선택지 집합이 보존됐는지 기계적으로 비교함. 정답 분포는 각 126개이며 전문 타당성 입증과 별도임.
- `node qa/question_bank_review_export.js --out review-artifacts`는 534개 고유 ID, 정답, 해설, 선택지, 출처, 위험도, 2인 전문가 검토 칸이 있는 CSV와 JSON 요약을 작성함.
- **시험 품질·공식 교육 승인: NO-GO.** 자동 구조검사 성공, 문항 수, APK 서명은 교육·군 보안 승인 증거가 아님.

## 4. 전문가 검토 규칙 (권고안)
1. 분야별 전문가 **2인이 서로의 답안을 보지 않고** 각 문항의 정답 유일성, 선택지의 조건부 참·거짓, 해설 및 참조 원문의 직접적 관련성을 판정한다.
2. 두 판정이 충돌하거나 정답 후보가 복수인 경우 사용을 보류하고, 제3검토자 조정 후 문항을 수정·재검토한다.
3. 모든 문항에 학습목표 ID, 출처의 구체적 절/버전, 생성·수정 이력 및 최종 검수자 기록을 남긴다.
4. 군 현업 역량은 실제 군 자료가 아닌 **비식별·합성** 정책기획, DB 조인, 데이터 품질, RAG 접근통제, 사업 경제성/TEV&V 사례로 평가한다.
5. 통과 문항만 파일럿에 투입하며, 파일럿의 응답자료는 최소수집·명확한 동의를 전제로 분석한다. 적합한 표본설계 없이 정답률·변별도·신뢰도 수치를 추정하지 않는다.
6. 문항 승인과 실습 결과 자체 점검은 공식 교육 승인 및 군 임무 수행 권한과 별개다.

## 5. Android 에뮬레이터 진단 교정 기록
- v2.3.3 개발 브랜치의 한 에뮬레이터 실행에서 `FATAL EXCEPTION: UiAutomation`이 관찰되어 기존 범용 패턴 `FATAL EXCEPTION` 검사로 시험이 실패했다.
- 당시 로그상 예외는 Android UI자동화 도구에서 발생했고 해당 앱 프로세스의 명시적 `Process: com.sungok2.armyaiacademy` 크래시 기록은 확인되지 않았다. 따라서 **이 실패만으로 앱 결함을 확정하지 않는다**.
- smoke 스크립트는 Android의 선택적 `uiautomator dump` 호출을 제외하고, 앱 프로세스의 명시적 크래시 기록만 실패로 판정하도록 바꿨다. 장치 재시작 후 앱 PID 확인, 스크린샷 기록, 크래시 로그 보관은 유지한다.
- 테스트용 합성 로그로 (1) 외부 `UiAutomation` 예외 무시, (2) 앱 크래시 탐지, (3) 정상 로그 통과를 검증한다.
- 수정된 시험의 GitHub Actions 결과가 통과하더라도 실제 삼성 갤럭시 실기기 검증은 별도 필요하다.
